PROJECT 01 / 03AI SYSTEMS · COMPUTER ARCHITECTURE

Kernellum.

What if hardware architecture search used the actual constraints of routing, rather than stopping at theoretical performance?

I built a closed-loop search pipeline that moves from candidate architectures to RTL, synthesis, place-and-route, and back to the next decision. Physical feedback changes what the system chooses.

23.56%Mean modeled latency gain against the best broadcast-only design
1.44%Mean regret relative to the full routed oracle

Scope matters. ECP5 final-route FPGA implementation results; latency is model-derived from cycle counts and final routed timing, not measured on an FPGA board. Resource use also increases.

PROJECT 02 / 03SCIENTIFIC DISCOVERY · REPRESENTATION

Theorica.

Can a system discover a more useful representation by using its own failed predictions?

I built an adaptive reconstruction method for algebraic operations. The first frozen cross-family run failed on nonassociative loops. The failure revealed a missing step: counterexamples should trigger acquisition of new structure, not just rejection.

345/345Exact reconstructions among eligible public holdout cases after correction
0/150False acceptances on the out-of-promise controls

Scope matters. This is a defined algebraic reconstruction benchmark with an eligibility promise. It is not evidence of general-purpose autonomous scientific discovery.

PROJECT 03 / 03SHIPPED PRODUCT · ON-DEVICE AI

Somno.

How do you make fatigue awareness useful without requiring an expensive wearable?

I built an Android app that combines reaction-time testing, on-device facial signals, self-reported sleepiness, and sleep history into a personal fatigue estimate. The raw face images stay local, and the app is available as a public release.

02 HOW I WORK

The interesting part is usually where it fails.

These aren't rules I always get right. They're the ones I keep coming back to.

  1. 01

    Make the claim testable.

    Choose the benchmark, the threshold, and the baseline before celebrating the result.

  2. 02

    Keep the uncomfortable evidence.

    A failed run should stay visible, especially if it changed the method.

  3. 03

    Care about the boundary.

    Simulated timing isn't a board measurement. A promising benchmark isn't universal intelligence.

  4. 04

    Leave a path to reproduce it.

    Publish code, exact reports, and the assumptions someone else would need to check my work.
